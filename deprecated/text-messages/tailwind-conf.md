I have a library of react components (`pk-ts-fe-lib`) I developed myself, which I use in my other web applications - currently `my-next-app`. 

I include this in the `package.json` file of `my-next-app` as a dependency with a github url: `"pk-ts-fe-lib": "github:pkirkaas/pk-ts-fe-lib#working",`

My fe-library implements a simple web page so I can test my components in the library before importing them into my web application.

All this has worked perfectly, until I tried to use Tailwind CSS in the library. I have created a responsive `NavBar` component in my library based on `tailwindcss`, the `daisyUI` component library for `tailwindcss`, and `react-daisyui` for prebuilt react components.

This works fine in my library, but when I try to use it in my web application, it is not responsive - it only shows the dropdown/mobile menu on the left hand side of the page, regardless of the screen size. It seems that the CSS generated by `tailwindcss` which works in the library is not being included in application, although the `tailwindcss` classes DO appear in the generated code installed in `my-next-app` (see below).


Details:

Both my library and my web application are using latest `typescript` and `react` and `esm` modules.

For local testing of the library components within the library, I use `vite` to serve the library.

My actual web application is built using `nextjs` 14 and `typescript`. 

Any daisy components I create in my web application work as expected - just not the custom daisy components I import from the library.

I understand that for performance reasons, Tailwindcss only generates CSS for the components that are actually used in the page. So component libraries like `daisyUI` and `react-daisyui` require a custom configuration of the `tailwind.config.ts` file to generate the CSS for the components. I tried to follow that pattern like this:
```ts

    'node_modules/pk-ts-fe-lib/dist/**/*.js', // My attempt to include my library in the tailwind.config.ts file
```
